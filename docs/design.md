# mirelab 설계 노트

독서 스터디(5인)를 노션 대신 운영하기 위한 자체 서비스. 경제 스터디는 같은 구조로 나중에 얹는다.

와이어프레임: https://claude.ai/code/artifact/897012d8-fc99-4dfa-97aa-430d4a9fcb51

---

## 1. 왜 만드는가

노션으로 운영 중이지만 세 가지가 구조적으로 안 된다.

### 뷰가 6종류로 고정

노션은 테이블·보드·갤러리·리스트·캘린더·타임라인 밖으로 못 나간다. 릴레이션과 롤업은 되지만, 원하는 모양으로 데이터를 재조합할 수 없다. **뷰를 코드로 짤 수 있다는 것**이 자체 개발의 유일하게 정당한 이유다.

에디터 성능이나 UI 완성도로는 노션을 못 이긴다. 이기려 들면 진다.

### 글과 데이터가 분리돼 있다

노션에는 세계가 둘이다.

- **블록** — 페이지 본문. 자유롭지만 그냥 텍스트
- **DB 속성** — 표의 열. 계산·정렬은 되지만 페이지 안에서 자연스럽게 못 씀

별점이 대표적이다. 감상문 안에 `★★★★☆`라고 쓰면서 동시에 평균 별점도 뽑고 싶은데, 노션은 이 둘을 잇지 못한다. **같은 값을 두 군데 쓰고 고칠 때도 두 군데 고친다.** 지금은 템플릿으로 때우고 있다.

→ 자체 개발하면 이 구분 자체가 없다. 화면에서 별 4개를 누르면 그게 곧 DB 값이다.

### 같은 내용을 세 번 쓴다

멤버들의 실제 사용 패턴:

```
① 개인 노션에 정리
      ↓ 복붙
② 공용 페이지에 옮겨 씀
      ↓ 모임에서 다듬어짐
      ↓ 복붙
③ 다시 개인 노션으로
```

게을러서가 아니라 **개인 공간과 공용 공간이 다른 페이지**라 생기는 왕복이다. 스터디 페이지는 주차별로 흩어지니 "내 관점에서 이어지는 기록"이 거기서 안 나오고, 그래서 자기 것을 따로 갖고 싶어 한다.

→ 한 번만 쓰고, 개인 뷰와 공용 뷰가 **같은 데이터를 다르게 모으게** 한다.

## 2. 핵심 개념: 칸(Slot)

콘텐츠를 페이지가 아니라 **이름 있는 칸** 단위로 저장한다. 각 칸은 무슨 값인지 시스템이 안다.

칸에는 축이 셋 있다.

| 축 | 값 | 의미 |
|---|---|---|
| **타입** | 별점 · 짧은 글 · 긴 글 · 목록 · 항목 목록 | 어떤 UI로 그리고 어떻게 저장하나 |
| **범위** | 개인별 · 공동 | 사람마다 하나씩인가, 주차에 하나인가 |
| **공개** | 항상 · 마감 후 · 계속 비공개 | 언제부터 남에게 보이나 |
| **소속** | 스터디 · 주차 | 매주 나오나, 이번 주만인가 |

### 소속 = 콜아웃의 일반화

지금 노션에서 필요할 때 콜아웃을 붙이는 행위가 **소속이 주차인 칸**이다. 별도 개념이 필요 없고, 몇 주 써보고 좋으면 "스터디 칸으로 올리기" 클릭 한 번으로 템플릿에 편입된다.

### 공개 = 개인 정리를 앱 안으로 흡수하는 장치

멤버들이 개인 정리를 이 앱 안에서 하고 싶어 한다. 그러려면 두 가지가 필요하다.

- **비공개 초안** — 마감 전엔 내 칸이 나만 보인다. 개인 노션에 먼저 쓸 이유가 사라진다 (①번 복붙 제거)
- **계속 비공개인 칸** — 공용에 안 올릴 잡생각을 담는 곳. 이게 없으면 결국 개인 노션을 계속 쓴다

### 공동 칸 = 항목 목록 + 메모

공동 문서와 개인 관점은 성격이 다르다. 한 텍스트에 섞으면 공동 문서는 누구 말인지 모를 잡탕이 되고, 개인 생각은 눈치 보느라 안 써진다.

그래서 **공동 칸은 항목 목록으로 통일**하고, 각 항목에 개인 메모를 붙인다.

```
줄거리 (공동)
  1. 농업혁명은 생산량을 늘렸지만 개인의 삶은 오히려 나빠졌다
       💬 지현   인구압 얘기랑 순환논증 아닌가?
       💬 준영   4장에 반박 나옴
  2. 화폐는 상호 신뢰의 시스템으로 작동한다
       🔒 나     실무랑 연결해서 생각해볼 것
```

메모는 **그 자리에 남으면서 내 기록에도 인용과 함께 쌓인다.** 따로 담아올 필요가 없다 (③번 복붙 제거).

> 공동 칸의 타입을 항목 목록 하나로 고정한 이유: 메모가 붙는 단위가 일관돼야 한다. 어떤 칸은 항목이고 어떤 칸은 흐르는 글이면 앵커가 두 종류가 된다. 긴 글이 필요하면 항목 하나를 길게 쓴다.

### 독서 스터디 초기 칸 구성

| 이름 | 타입 | 범위 | 공개 |
|---|---|---|---|
| 평점 | 별점 | 개인별 | 항상 |
| 한줄평 | 짧은 글 | 개인별 | 항상 |
| 인상깊은 장면 | 목록 | 개인별 | 마감 후 |
| 내 메모 | 긴 글 | 개인별 | 🔒 계속 비공개 |
| 줄거리 | 항목 목록 | 공동 | 메모 허용 |
| 오늘 나온 이야기 | 항목 목록 | 공동 | 메모 허용 |

## 3. 데이터 모델

```
Study ─┬─ Member
       ├─ SlotDef ─────┐         소속: 스터디
       └─ Week ────┬───┤         소속: 주차 (콜아웃)
                   │   │
                   │   └─ SlotValue  (칸, 주차, 작성자, 값)
                   └─ Book
                              Memo  (주차, 칸, 항목ID, 작성자, 본문, 공개여부)
```

### SlotValue.value 는 JSONB

칸 타입이 사용자 마음대로 늘어나니 컬럼을 미리 못 만든다.

```jsonc
{"n": 4}                                    // 별점
{"text": "후반부가 늘어지지만…"}             // 짧은 글 / 긴 글
{"items": ["밀을 길들이지…", "화폐는…"]}     // 목록
{"yjs": "<binary>"}                          // 공동 항목 목록
```

평점 통계는 그냥 집계한다. 두 번 쓸 일이 없다.

```sql
select avg((value->>'n')::numeric)
from slot_value where slot_def_id = ?
```

### 공동 칸의 소유권 분리

- **항목 본문** — Yjs가 소유. `SlotValue.value.yjs` 에 바이너리로 저장
- **메모** — DB가 소유. `/me` 에서 모아 보려면 질의 가능해야 한다
- **연결** — Yjs 항목이 가진 고유 id 를 `Memo.itemId` 가 참조

### 인증은 나중에, 작성자는 지금부터

로그인은 뒤로 미루되 **`Member` 테이블과 `SlotValue.memberId` 는 지금 만든다.** 나중에 붙이면 이미 쌓인 데이터가 주인 없는 상태가 된다. 스터디 성격상 "누가 썼는가"가 데이터의 절반이다.

- 지금: 헤더에서 멤버 전환 (개발용 · 5인 화면 테스트에 오히려 편하다)
- 나중: 카카오 로그인 등
- 프론트는 `useCurrentUser()` 훅 하나로 감싸두고, 나중에 그 안쪽만 교체

⚠️ **로그인 붙기 전엔 배포 금지.** 아무나 아무 멤버로 글을 쓸 수 있다.

## 4. 화면

| 순위 | 화면 | 경로 | 요지 |
|---|---|---|---|
| P0 | 이번 주 | `/` | 제출 현황 한 줄 + 안 쓴 사람 찌르기 |
| P0 | 주차 상세 | `/w/:n` | 개인 칸 / 공동 칸. 칸 정의대로 렌더 |
| P0 | 칸 관리 | `/settings/slots` | 추가·정렬·숨김. "나만의 노션"이 되는 지점 |
| P0 | 비공개 초안 · 멤버 전환 | — | 없으면 다들 노션으로 돌아간다 |
| P1 | 내 기록 | `/me` | 내가 쓴 것 + 메모 + 마크다운 내보내기 |
| P1 | 책 검색 · 주차 만들기 | `/w/new` | 제목만 치면 표지·저자·쪽수 자동 |
| P1 | 서재 · 책 상세 | `/books` `/books/:id` | 별점 칸 하나로 두 화면이 나온다 |
| P1 | 리마인더 | — | 마감 전 자동 알림 |
| P2 | 로그인 · 배포 | — | 그 전엔 로컬에서만 |
| P2 | 통합 검색 · 통계 | — | 기록이 쌓인 뒤에 필요해진다 |

### 프론트 구조의 핵심

칸 타입마다 렌더러를 하나씩 두고 타입으로 찾아 쓴다. 주차 화면은 칸 목록을 받아 순서대로 뿌리기만 한다.

```
RENDERERS = {
  RATING:     별 다섯 개
  TEXT_SHORT: 한 줄 입력
  TEXT_LONG:  textarea
  LIST:       목록 + 추가
  SHARED:     항목 목록 (Yjs) + 메모
}
```

**새 칸 타입 추가 = 렌더러 하나 추가.** 경제 스터디용 타입을 붙일 때도 이 구조가 그대로 간다.

### 속도가 곧 기능

개인 정리를 여기서 하려면 쓰기가 답답한 순간 노션으로 돌아간다. 노션을 떠나는 이유가 버벅임이었다는 걸 잊지 말 것.

- 자동 저장 (제출 버튼을 기다리지 않는다)
- 낙관적 업데이트 — 스피너를 보여주지 않는다
- 모바일은 확인 + 짧은 입력까지. 긴 글과 실시간은 데스크톱

## 5. 기술 결정

### 노션식 블록 에디터는 만들지 않는다

Tiptap/ProseMirror 불필요. `긴 글` 칸은 그냥 textarea. `/` 명령어도, 블록 드래그도, 마크다운 파싱도 없다. **프로젝트 규모가 절반으로 줄어든다.**

애초에 노션의 자유로운 블록이 위 2번 문제(별점을 두 번 쓰는 것)를 만든 원인이라 버리는 게 맞다.

### 실시간 공동 편집 — Yjs

직접 구현하지 않는다. CRDT라 충돌 해결이 수학적으로 보장된다.

서버는 CRDT를 이해할 필요가 없다. Yjs 업데이트는 불투명한 바이트 덩어리고 순서가 뒤바뀌어도 결과가 같으므로, **Spring은 받아서 뿌리고 저장만 한다.**

```
브라우저 A ─┐                          ┌─ 바이너리 그대로 중계
브라우저 B ─┼─ WebSocket ─ Spring ─────┤
브라우저 C ─┘                          └─ DB에 통째로 저장
```

실시간은 **공동 칸에만** 붙는다. 개인 칸은 그냥 저장이라 범위가 작다.

### 외부 API

- **책** — 알라딘 OpenAPI (국내 커버리지 최고, ISBN·표지·목차)
- **영화** — TMDB (포스터, 한국어 지원)

표지 이미지는 등록 시점에 받아서 우리 쪽에 보관한다. 외부 URL을 그대로 쓰면 나중에 깨진다.

### 프론트 스택

Vite 8 · React 19 · TypeScript · React Router · TanStack Query · Tailwind v4 · oxlint + Prettier

- `/api` → `localhost:8080` dev 프록시. 브라우저 기준 same-origin이라 **백엔드 CORS 설정 불필요**
- `@/` → `src/`
- API는 `src/lib/api.ts` 의 fetch 래퍼. 실패 시 `ApiError(status, body)`
- `queryClient` 는 4xx 재시도 안 함, 5xx만 2회

⚠️ `erasableSyntaxOnly` 가 켜져 있어 **enum과 생성자 파라미터 프로퍼티를 못 쓴다.** enum 대신 `as const` 객체 + 유니온 타입.

### 백엔드 스택

Kotlin 2.3 · Spring Boot 4.1 · JPA · Postgres (개발 중 H2)

## 6. 정책 결정

| | 결정 |
|---|---|
| 칸 삭제 | **지우지 않고 숨김.** 새 주차엔 안 나오고 과거 기록은 남는다. 몇 달치 감상문이 날아가면 안 된다 |
| 칸 구성 변경 | 과거 주차도 새 구성을 따른다. 주차별 박제는 구현이 복잡한 데 비해 5인 스터디에서 얻는 게 없다 |
| 칸 타입 변경 | **막는다.** 새 칸을 만들어 옮기도록 안내. 변환 경우의 수가 폭발하는데 실제로 거의 안 일어난다 |
| 슬롯 정의 UI | 화면에서 만든다. 다만 독서 스터디 초기 구성은 위 표대로 시작 |

## 7. 미결

1. **초안 공개가 자동인가 수동인가** — 자동이면 깜빡해도 공유되고, 수동이면 "아직 안 다듬었는데" 부담이 없다. 둘 다 두면 규칙이 흐려지니 하나만 고른다
2. **메모 달린 항목이 지워지면** — 모임 중 항목을 정리하다 지우는 일이 생긴다. 메모도 사라질지, 인용을 굳혀 내 기록에 남길지
3. **메모 기본값이 공개인가 비공개인가** — 공개가 기본이면 대화가 늘고, 비공개가 기본이면 솔직해진다
4. **리마인더 채널** — 메일이 제일 쉽고, 디스코드 웹훅이면 하루면 붙는다. 카톡 알림톡은 사업자 등록 필요

전부 컬럼 값이나 화면 동작 수준이라 구조를 뒤집지 않는다. 만들면서 정해도 된다.
